# Tealback pistol (Roblox, box-built pixel art)

Everything in `out/` and `previews/` is generated by `build_pistol.py` (`pip install numpy pillow`, then `python3 build_pistol.py`). To change the gun, edit the box table (`BOXES`) and the painters, then run the script again.

## Files

| File | What it is |
|---|---|
| `out/pistol.glb` | The file to import. It has 4 separate meshes (Body, Slide, Magazine, Trigger), each with its outline shell merged in, and the 1024 texture embedded. Units are studs. |
| `out/pistol_1024.png` | The 128px texture scaled up 8x with nearest-neighbour. **Upload this one to Roblox.** |
| `out/pistol_128.png` | The source texture: 1 texel = 1 model unit on every face. |
| `out/pistol.obj` + `.mtl` | The same 4 objects (`o`/`g` per part), with `map_Kd` pointing to `pistol_1024.png`. |
| `out/pistol.bbmodel` | Blockbench project (Generic Model format, 128 texture embedded, one group per part, the grip boxes rotated -15° on X). It holds only the real boxes; the outline shells are not in it (see the notes below). |
| `out/build_info.json` | Measured sizes, offsets, triangle counts. |
| `previews/` | Side, top, front and 3/4 views, with and without outlines, plus an action pose and the texture. |

## Numbers (origin = grip centre; +Y up; barrel along -Z; 16 px = 1 stud)

- Size of the real geometry: 34.25 L × 23.4 H × 9 W px (2.14 × 1.46 × 0.56 studs). The slide is 7 px wide, the compensator and receiver are 9 px wide.
- **Muzzle tip** (centre of the compensator's front face): `(0, 0.594, -1.688)` studs from the origin, or `(0, 0.362, -1.074)` from the centre of the Body MeshPart.
- **Slide travel:** 5 px = **0.3125 studs** back along +Z. At full travel the barrel shows between the slide and the compensator.
- **Trigger:** 1 px = 0.0625 studs back along +Z.
- **Magazine drop:** along `(0, -0.966, 0.259)` (straight down the 15° grip axis). 0.75 studs clears the grip.
- **Tool.Grip** (with Body as the Handle): `CFrame.new(0, -0.232, 0.613)`.
- Triangles: Body 218, Slide 96, Magazine 50, Trigger 24, outlines included.

## Roblox Studio import (keeps the parts separate)

1. Open **Import 3D** (Home or Avatar tab, or File → Import 3D) and pick `pistol.glb`.
2. In the importer settings:
   - Turn **Merge Meshes** off. This is what keeps the 4 parts separate.
   - Set **Scale Unit** to **Stud**. The file is already in studs, so the Body should come in at about 0.63 × 1.29 × 2.21 studs.
   - Turn **Insert Using Scene Position** and **Set Pivot to Scene Origin** on, so the parts line up and the pivot sits at the grip.
   - Leave World Forward and World Up at their defaults. Then check that the barrel points along the model's -Z (its LookVector). If it comes in backwards, re-import with World Forward flipped.
   - Option names vary a little between Studio versions. Merge Meshes off and the stud scale are the two settings that matter.
3. You get a Model containing MeshParts named Body, Slide, Magazine and Trigger. Check that each one's `TextureID` is set. If it is empty, upload `pistol_1024.png` (Asset Manager → Import) and paste its id into the `TextureID` of all four parts.
4. On each MeshPart, set **RenderFidelity = Precise**. If you leave it on Automatic, Roblox's level-of-detail meshes can drop the outline shells at a distance. Also set CollisionFidelity = Box, CanCollide = false and Massless = true.
5. Make a Tool:
   1. Rename Body to `Handle` and move it into the Tool.
   2. Join Slide, Magazine and Trigger to the Handle with Motor6Ds (`Part0 = Handle`, `C0 = Handle.CFrame:Inverse() * part.CFrame`, `C1 = CFrame.new()`).
   3. Set `Tool.Grip = CFrame.new(0, -0.232, 0.613)`.
   4. Animate by offsetting each Motor6D's C0 by the travel distances above. For example, the slide is `C0 * CFrame.new(0, 0, 0.3125)`.

### Keeping the texture sharp in Roblox

- Upload the 1024 nearest-neighbour PNG, never the 128 one. Roblox filters textures bilinearly, so the 128 version would blur across every pixel. At 8x the blur only touches the last texel of each 8×8 block, so the pixels stay square.
- Every UV island has a 1-texel pad of its own edge colour (8 px at 1024), so lower mip levels don't bleed neighbouring colours in.
- Don't put the texture in a SurfaceAppearance. A plain MeshPart `TextureID` keeps the painted colours exactly.
- At long range Roblox still drops to lower mip levels, and very low graphics quality settings can downscale textures. Nothing in the file can prevent that.

## Notes

- **How the outline works:** each part has an inverted-hull shell, made from the union of its boxes inflated by 0.5 px, with faces pointing inward. Every shell vertex samples one solid black 8×8 block in the same texture, so the outline is texture pixels, not a separate material. Because the shell is a union rather than one box per piece, it adds no stray lines where boxes meet flush. Back-face culling has to be on, which is the default (`DoubleSided = false`).
- **Blockbench:** a cube can't be turned inside out, so the .bbmodel has no outline shells. The script is the source of truth. If you change boxes in Blockbench, copy the new numbers into `BOXES` and run the script again, rather than exporting from Blockbench, which would drop the outlines.
- I checked the .bbmodel by rebuilding it with Blockbench's own cube and UV rules (taken from Blockbench's source) and rendering it. It matched the GLB pixel for pixel. I have not opened it in the Blockbench app itself.
